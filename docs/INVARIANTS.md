# Invariants: specification and enforcement

Each invariant is stated, then enforced in code where possible, then checked by tests. If a test for an invariant fails, development stops until the failure is understood.

| # | Invariant | Enforced in code | Checked by |
| --- | --- | --- | --- |
| 1 | **Determinism.** Same inputs and method version give byte-identical results and receipts. | All arithmetic runs on `Decimal` under one pinned context (`_decimal.py`), and its correctly rounded ln, exp and sqrt are platform-independent. Canonical JSON (`canonical.py`) rejects binary floats. Inputs are normalized: sorted, with defaults written out, and idempotent. The core reads no clock, randomness, environment or network, and a receipt holds no timestamp unless the caller supplies `observed_at`. | `test_invariant_1_determinism.py`: repeated runs; shuffled key, list and link order; float, string and Decimal inputs; fresh processes with different `PYTHONHASHSEED`; idempotent normalization; clock, network and random patched to raise. |
| 2 | **Monotonicity.** Adding verified habitat or connectivity never lowers the complexity score, all else equal. | ECA is a sum of non-negative terms over max-product paths, and decimal rounding is monotone. Unverified patches and their links are excluded. | `test_invariant_2_monotonicity.py`: more than 2 000 seeded mutations (new patch, larger area, better condition, newly verified patch, new link of each kind, higher probability, shorter gap) and the effect of unverified additions. |
| 3 | **Bound respected.** Complexity capacity never exceeds the stated bound for the given inputs. | phi = min(1, ECA/A_v); C = min(B, connectivity term, channel term); a hard guard raises if C > B. | `test_invariant_3_bound.py`: 1 500 random sites, an independent recomputation of B, the fully connected limit (C = B), channel limits and extreme inputs. |
| 4 | **Conservation.** Releases plus remaining balance always equal total pledges; no release without a met milestone. | Integer minor units; latched milestones and ratcheted outcome progress; a per-pledge, per-rule floor; sum of bps <= 10 000; runtime assertions in every period. | `test_invariant_4_pool_conservation.py`: 600 random pools, no-observation pools, gating by earliest period, ratchet with late pledges, receipt-only rules, tampered receipts, receipts for another site, invalid specs. |
| 5 | **No money movement.** No payment SDKs, private keys, wallet code or token minting. | The core uses only the standard library; the only third-party imports are `mcp` and `uvicorn`, in `mcp_server.py`. | `test_invariant_5_no_money.py`: greps every repository file for SDK imports, key material, wallet, mint and transfer patterns; checks dependency manifests and source imports. |
| 6 | **Read-only externally.** Only public data is read; nothing is written anywhere. | `vergecommon.py` builds only `Request(url, data=None, method="GET")` to an HTTPS allowlist, with no credentials and a size cap. MCP tools are annotated read-only and idempotent. `src/` has no file writes. | `test_invariant_6_read_only.py`: AST and regex scans; a runtime spy on every request; global `urlopen` patched; host and scheme rejection; MCP annotations. |
| 7 | **Honest labels.** Every output that uses the intelligence bound carries "conjecture" in its explanation field. | `valuation.evaluate` raises if a valuation using the bound lacks the label; every bound-derived quantity has `status: "conjecture"`. | `test_invariant_7_labels.py`: valuations, explanations, receipt verification, pool simulations, method description and MCP tool outputs. |

Spec-level limits are also tested: the README carries the legal-review notice, docs and tool text avoid financial-product vocabulary, and the method version is pinned to a reference digest (`test_docs_and_vocabulary.py`).
